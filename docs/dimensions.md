# 해설 차원 정의

`product-spec.md` 7절의 차원 목록이 원본이다. 이 문서는 그 차원들을 엔진이 계산할 수 있는 형태로 내려가는 자리이며, **명리 규칙 대응표는 아직 비어 있다.** 이 표가 채워지기 전에는 `saju` 엔진의 `compare()`를 구현할 수 없다.

## 시주 의존 처리

- `high`: 한쪽이라도 `hasBirthTime=false`면 `CompatibilityVector.hiddenDimensions`에 넣고 결과에서 숨긴다.
- `mid`: 계산은 하되 Narrative에 "출생시간이 더해지면 더 정밀해져요" 안내를 붙인다.
- `low`: 영향 없음.

## 점수 → 단계

| 내부 점수 (0~1) | 단계 식별자 | 사용자에게 보이는 표현 |
| --- | --- | --- |
| 0.67 이상 | `aligned` | 잘 맞아요 |
| 0.34 ~ 0.66 | `different` | 다른 결이에요 |
| 0.33 이하 | `tense` | 부딪힐 수 있어요 |

경계값은 첫 사용자 테스트 뒤 조정한다. 총점은 계산하지 않는다.

**유사도 척도 계수 (SIMILARITY_SCALE = 2).** 유사도 차원의 점수는 `1 − |a − b| × 2` (0~1로 자름)다. 계수 1로 두면 무작위 300명·600쌍 기준으로 "잘 맞아요"가 70~85%로 쏠리고 "부딪힐 수 있어요"가 1% 미만이었다(2026-10-19 확인). 계수 2에서는 대략 아래 분포다. 실제 사용자 쌍에서 다시 확인한다.

| 차원 | 잘 맞아요 | 다른 결이에요 | 부딪힐 수 있어요 |
| --- | --- | --- | --- |
| communication | 26% | 48% | 26% |
| emotional | 50% | 34% | 16% |
| pace | 41% | 29% | 31% |
| friction (분류 규칙, 계수 무관) | 46% | 32% | 22% |

## 엔진 계산의 두 단계

```
derive(sourceData)  → traitDimensions: { <차원>: { a: 개인값(들) } }
compare(A, B, type) → dimensions:      { <차원>: 0~1 }
```

`derive()`는 개인 한 명의 성향을 차원별로 뽑고, `compare()`는 두 사람의 성향을 차원별 규칙으로 맞물려 점수를 낸다. 같은 차원이라도 "비슷할수록 좋은" 것(pace)과 "보완될수록 좋은" 것(role)이 있으므로, 차원마다 비교 규칙을 따로 정한다.

## 명리 규칙 대응표 (미완 — 기획자/명리 자문이 채운다)

각 차원에 대해 세 가지를 정해야 한다.

1. **개인값**: 한 사람의 명식에서 이 차원을 읽는 데 쓰는 요소. 예: 일간의 음양, 특정 십신의 유무·위치·개수, 오행 분포의 편중, 지지의 특정 조합.
2. **비교 규칙**: 두 사람의 개인값을 어떻게 맞물려 0~1로 만들 것인가. 예: 같으면 높음 / 상생이면 높음 / 한쪽이 있고 한쪽이 없으면 중간.
3. **문장 단서**: 개인값이 어떤 행동 묘사로 번역되는가. `narrative-templates.md`의 관찰 문장에 들어간다.

### 공통 계산 방식 (검토 대기)

모든 차원은 같은 세 단계로 계산한다.

1. **세기** — 명식 여덟 글자(시주 없으면 여섯 글자)에서 십신 분포와 오행 분포를 센다. 자리 가중치: 월지 2.0, 일지 1.5, 그 외 천간·지지 각 1.0. 지장간은 첫 버전에서 쓰지 않는다.
2. **축으로 바꾸기** — 차원마다 정의한 "축"에 해당하는 십신·오행의 가중 비중을 0~1로 정규화한다. 축 값 0.5가 중립.
3. **맞물리기** — 비교 규칙에 따라 두 사람의 축 값을 0~1 점수로 만든다. 기본은 유사도 `1 − |a − b|`. friction은 예외(아래).

가중치·경계값은 첫 사용자 테스트 뒤 조정한다. 십신 명칭은 코드에서 `bijian, geopjae, siksin, sanggwan, pyeonjae, jeongjae, pyeongwan, jeonggwan, pyeonin, jeongin`으로 쓴다.

| 차원 | 개인값 (명식 요소) | 비교 규칙 | 문장 단서 | 상태 |
| --- | --- | --- | --- | --- |
| communication | **순서축**: (상관+편재 비중, 양간이면 +0.1) vs (식신+정인 비중, 음간이면 +0.1) → 0=맥락 먼저, 1=결론 먼저. **속도축**: (비겁+상관 비중) vs (인성+정관 비중) → 0=듣고 답함, 1=바로 말함 | 두 축 각각 유사도를 구해 평균. 두 축 모두 차이 ≤0.3이면 aligned 영역, 하나만 크면 different, 둘 다 크면 tense | 순서축 ≥0.6 → `direct`, ≤0.4 → `contextual`; 속도축 ≥0.6 → `quick`, ≤0.4 → `listener`; 중립이면 더 치우친 축의 단서를 쓴다 | 구현됨 v0.1.0 (검토 뒤 조정) |
| emotional | **표출축**: (화 오행 + 상관 + 겁재 비중) vs (수 오행 + 정인 + 편인 비중). 금 오행 비중은 양쪽에 0.5씩 → 0=안으로 삭임, 1=겉으로 드러냄 | 유사도. 단, 둘 다 ≥0.8이면 결과를 한 단계 내린다(같은 방향 과열) | ≥0.65 → `expressive`(감정이 빨리 올라오고 겉으로 보이는 편), ≤0.35 → `contained`(안에서 오래 머무는 편), 그 사이 → `steady`(표현은 적지만 꾸준한 편) | 구현됨 v0.1.0 (검토 뒤 조정) |
| pace | **추진축**: (비겁+상관+편관 비중) vs (정인+정관+정재 비중) → 0=충분히 보고 움직임, 1=일단 움직임 | 유사도 | ≥0.6 → `fast`(결정도 수정도 빠른 편), ≤0.4 → `deliberate`(확인하고 움직이는 편), 그 사이 → `moderate` | 구현됨 v0.1.0 (검토 뒤 조정) |
| friction | **일간 오행 관계** + **일지 관계**. 축이 아니라 분류값 | 일간 상생 또는 천간합 → 0.8 / 같은 오행 → 0.5 / 상극 → 0.25. 일지 합(육합·삼합) +0.15, 일지 충 −0.15. 0~1로 자름 | 상극일 때 극의 방향으로 장면 결정: 목극토 `push-hold`(밀어붙임 vs 버팀, 주도권), 토극수 `frame-flow`(틀 잡기 vs 흘러가기, 자유도), 수극화 `cool-heat`(식힘 vs 달아오름, 온도), 화극금 `melt-hold`(녹임 vs 지킴, 원칙), 금극목 `cut-grow`(자르기 vs 뻗기, 간섭). 상생 → `feed`(한쪽이 채워주는 사이), 동오행 → `mirror`(닮아서 편하지만 같은 것을 두고 겨루기 쉬운 사이) | 구현됨 v0.1.0 (검토 뒤 조정) |

- emotional에 오행을 섞는 것이 과한가. 십신만으로 가려면 (상관+겁재) vs (정인+편인)으로 단순화.

- 모든 비교 규칙이 "비슷할수록 좋음"이다. 유형별 차원(예: coworker의 role)은 "보완될수록 좋음"이 필요하며 그때 비교 규칙 종류가 하나 늘어난다.

## 만세력 관례 (엔진 v0.1.0에서 채택한 것)

생년월일시 → 네 기둥 계산은 `lunar-typescript` 라이브러리에 맡기고, 아래 보정과 관례를 우리 코드(`packages/engine-saju/src/calendar.ts`)에서 적용한다. 테스트 `test/calendar.test.ts`가 각 항목을 고정한다.

| 항목 | 채택한 관례 | 이유·비고 |
| --- | --- | --- |
| 절기 시각의 시간대 | 라이브러리는 중국 표준시 기준이므로, 연주·월주 판정 시 입력 시각에서 1시간을 뺀다 | 한국천문연구원 절입 시각과 맞춤. 예: 2024 입춘 17:27 KST |
| 일주 경계 | 정자시법. 23:00부터 다음 날 일주 | 한국 주류 관례. 야자시 구분은 쓰지 않음 |
| 시주 구간 | 23:00~00:59 子時 등 두 시간 단위 | 표준 |
| 출생시간 모름 | 정오로 간주해 연·월·일주 계산, 시주 null | 절기일 정오 전후 출생자는 월주가 틀릴 수 있음. 안내 문구 검토 |
| 음력 입력 | 라이브러리의 음력→양력 변환. 윤달은 별도 플래그 | 1900~2100 범위 |
| 진태양시 보정 | 적용하지 않음 | 다음 버전. 적용 시 약 −30분, 시주 경계 출생자에게 영향 |
| 지장간 | 본기만 사용 | 첫 버전 단순화 |

## 엔진이 반드시 지켜야 하는 것

- 입력이 같으면 출력이 같다 (난수, 현재 시각, 외부 호출 없음).
- 개인값·비교 규칙은 이 문서에 적힌 것만 쓴다. 코드에만 있는 규칙은 없어야 한다.
- 규칙이 바뀌면 `engineVersion`을 올리고, 기존 Vector는 재계산 대상으로 표시한다.
- 대운·세운 등 시간에 따라 변하는 요소는 첫 버전에서 쓰지 않는다 (해설이 "지금의 두 사람"이 아니라 "타고난 결"에 머물도록).
